# Evidence Publication Instructions

[Evidence index and proposed filenames](../docs/EVIDENCE_INDEX.md) · [Overview](../README.md)

This directory is a placeholder for **actual, sanitized lab evidence**. No screenshots have been fabricated or included. The filenames in the index are proposals, not claims that artifacts exist.

## Before adding evidence

1. Use an actual lab capture and identify whether it represents historical or current state. Do not reconstruct missing historical screenshots.
2. Remove tenant IDs, device IDs, recovery keys and protector IDs, passwords, tokens, user identities beyond approved lab aliases, sensitive paths, network details, and unrelated infrastructure data.
3. Use irreversible cropping or opaque redaction on a flattened copy; inspect the saved output at full resolution and remove sensitive metadata. Preserve the original privately.
4. Publish selected properties or a sanitized summary, not sensitive raw logs, complete diagnostic bundles, transcripts, or backups. Never publish complete BitLocker protector output.
5. Confirm filenames and captions describe only what the capture demonstrates. An audit event is not proof of compromise; a successful reset or compliance result does not prove unrelated controls.
6. Update the evidence index, then embed the real image beneath its matching implementation procedure. Check the link before committing.

Do not upload recovery-key portal screenshots containing a key. A redacted portal observation can document the scope of a review, but cannot establish absence in all recovery locations. No copyrighted benchmark PDFs or other restricted source documents should be uploaded.
